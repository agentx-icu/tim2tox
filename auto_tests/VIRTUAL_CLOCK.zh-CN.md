[English](./VIRTUAL_CLOCK.md)\n\n[English](./VIRTUAL_CLOCK.md)\n\n# 虚拟时钟模式 — 工程师指南\n\n> 语言 / Language: [English](VIRTUAL_CLOCK.md) | **简体中文**\n\n本文是为 `tim2tox/auto_tests` 编写或迁移虚拟时钟测试的详细指南。请配合 [README.zh-CN.md](README.zh-CN.md) 阅读：README 给出高层概览，本文覆盖 API 表面、常用模式、易错点和内部机制。\n\n**读者：** 编写或维护 mode-aware 场景文件的工程师。一个文件同时支持 wall-clock 和 virtual-clock 两种模式；仓库里没有 `*_virtual_test.dart` 兄弟文件，详见第 9 节。\n\n---\n\n## 1. 为什么需要虚拟时钟\n\nTox 协议里有大量以秒计的定时器：\n\n| 常量 | 值 | 用途 |\n|---|---|---|\n| `PING_INTERVAL` | 60 s | DHT keep-alive |\n| `BAD_NODE_TIMEOUT` | 122 s | DHT 节点淘汰 |\n| Onion path timeout | 10 s | 路径轮换 |\n| Friend reconnect | 5–10 s | P2P 重试节奏 |\n| Group announce / connect | 数秒 | NGC 发现 |\n\n在 wall-clock 模式下，每个定时器都会消耗真实时间；多实例 `setUpAll` 很容易在第一个测试体运行前就花掉 30–60 秒。虚拟模式把 Tox 协议时间从 wall time 中解耦：60 秒协议时间可以在毫秒级完成。\n\n虚拟模式**不会**压缩：\n\n- **Loopback UDP 投递。** 同进程兄弟实例之间的包仍要经过操作系统 socket buffer。`pumpTestTick` 正是因此会在 iterate 批次之间插入很短的 `wallSleep`（默认 5 ms）。\n- **内核操作**（UDP bind、文件 I/O）。`configureLocalBootstrapVirtual` 会在 UDP listener bind 附近保留真实 500 ms sleep，因为这是内核操作，不是 Tox 定时器。\n\n---\n\n## 2. 核心 API（位于 `test/test_helper.dart`）\n\n### `VirtualClock`\n\n纯静态类；每个进程只有一个虚拟时钟。\n\n| 成员 | 用途 |\n|---|---|\n| `VirtualClock.enableEarly()` | 必须在 `scenario.initAllNodes()` **之前**调用。它通过 `tim2tox_ffi_set_default_test_mode(1)` 设置进程级默认 `test_mode` 标志，让 `V2TIMManagerImpl` 构造函数继承该标志，并阻止 `InitSDK` 启动 `event_thread`。信令以及任何依赖 `task_queue` 由 `tim2tox_ffi_iterate_instance` 驱动的流程都需要它。它也会把虚拟时钟播种到 1000 ms。 |\n| `VirtualClock.enableForScenario(scenario)` | 在 `scenario.initAllNodes()` **之后**调用。它对每个节点测试实例调用 `tim2tox_ffi_set_test_mode(handle, 1)`，再把虚拟时钟播种到 1000 ms。该调用幂等，可重复执行。仅群组相关测试通常只调用它也足够，因为群流程通过 `tox_iterate` 前进，而 `event_thread` 和 `pumpTestTick` 都会驱动 `tox_iterate`。 |\n| `VirtualClock.advance(ms)` | 将共享时钟推进 `ms` 个虚拟毫秒。它不会触发 iterate；调用方必须随后执行迭代。需要“推进后迭代”的组合模式时优先用 `pumpTestTick`。 |\n| `VirtualClock.nowMs` | 当前虚拟时钟值，只读整数。 |\n| `VirtualClock.enabled` | 当前进程是否启用了测试模式。下面的 `*Virtual` helper 在它为 `false` 时会透明回退到 wall-clock 行为。 |\n\n### Pump 原语\n\n| 函数 | 用途 |\n|---|---|\n| `pumpTestTick(scenario, {advanceMs, iterationsPerInstance, wallSleep})` | 将虚拟时钟推进 `advanceMs`，迭代每个实例，然后为 loopback 投递 wall-sleep `wallSleep`。默认值：`advanceMs: 50`、`iterationsPerInstance: 1`、`wallSleep: 5 ms`。迭代次数会随 `advanceMs` 自动放大，公式为 `floor(advanceMs / 50)`，并以下限 `iterationsPerInstance` 兜底。有效迭代次数 >=10 时会分成 10 个批次，每批之间让出 2 ms wall time，让 loopback UDP 包落稳。 |\n| `pumpTestTickAv(scenario, ...)` | 与 `pumpTestTick` 相同，但还会对每个实例调用 `tim2tox_ffi_av_iterate`。ToxAV 测试必须使用它；默认 `pumpTestTick` 不会推进 ToxAV 的独立 iterate loop。 |\n| `waitUntilWithVirtualPump(scenario, cond, {timeout, advanceMs, iterationsPerInstance, wallSleep, description})` | 在 tick 虚拟时钟的同时轮询 `cond`。启用虚拟模式时 `timeout` 解释为虚拟毫秒，否则解释为真实毫秒。虚拟预算耗尽后抛出 `TimeoutException`。截止后还会执行 10 轮 microtask drain，让 native callback → ReceivePort → listener 链路有机会落地。 |\n| `waitUntilWithAvVirtualPump(scenario, cond, ...)` | AV-aware 版本；每轮同时 pump Tox 与 ToxAV iterate。 |\n\n当 `VirtualClock.enabled == false` 时，所有 pump 原语都会委托给 wall-clock 等价函数（`pumpAllInstancesOnce` / `waitUntilWithPump`），所以同一个 helper 可以服务两种模式。\n\n---\n\n## 3. `*Virtual` 替换表\n\n每个 wall-clock helper 都有对应的 virtual helper；virtual helper 会接收 `scenario`，并驱动共享时钟，而不是直接 `Future.delayed`。\n\n| Wall-clock | Virtual |\n|---|---|\n| `configureLocalBootstrap(scenario)` | `configureLocalBootstrapVirtual(scenario)` |\n| `establishFriendship(a, b, timeout: t)` | `establishFriendshipVirtual(scenario, a, b, timeout: t)` |\n| `node.waitForConnection(timeout: t)` | `waitForConnectionVirtual(scenario, node, timeout: t)` |\n| `node.waitForFriendConnection(fid, timeout: t)` | `waitForFriendConnectionVirtual(scenario, node, fid, timeout: t)` |\n| `pumpFriendConnection(a, b, duration: d)` | `pumpFriendConnectionVirtual(scenario, a, b, duration: d)` |\n| `pumpGroupPeerDiscovery(a, b, duration: d)` | `pumpGroupPeerDiscoveryVirtual(scenario, a, b, duration: d)` |\n| `waitUntilFounderSeesMemberInGroup(f, o, gid, timeout: t)` | `waitUntilFounderSeesMemberInGroupVirtual(scenario, f, o, gid, timeout: t)` |\n| `waitUntilWithPump(cond, timeout: t)` | `waitUntilWithVirtualPump(scenario, cond, timeout: t)` |\n| `Future.delayed(Duration(milliseconds: N))` | `pumpTestTick(scenario, advanceMs: N)` |\n| `pumpAllInstancesOnce(iterations: N)` | `pumpTestTick(scenario, advanceMs: 50, iterationsPerInstance: N)` |\n\n经验规则：如果原测试会 wait、sleep 或 pump，virtual 版本就应该调用对应的 `*Virtual` helper。把 wall-clock 的 `Future.delayed` 混进 virtual 测试不会破坏状态，但会浪费真实时间，因为虚拟时钟在这段时间里不会前进。\n\n---\n\n## 4. 标准 `setUpAll` 模式\n\n```dart\nsetUpAll(() async {\n  await setupTestEnvironment();\n\n  // Step 1: enable test mode BEFORE any test instance is created.\n  // This sets the process-global default so V2TIMManagerImpl's constructor\n  // reads test_mode = true and InitSDK never spawns event_thread.\n  await VirtualClock.enableEarly();\n\n  scenario = await createTestScenario(['alice', 'bob']);\n  alice = scenario.getNode('alice')!;\n  bob = scenario.getNode('bob')!;\n\n  await scenario.initAllNodes();\n\n  // Step 2: seed virtual clock & sync the per-instance flag for the handles\n  // that now exist. Idempotent w.r.t. enableEarly.\n  await VirtualClock.enableForScenario(scenario);\n\n  await Future.wait([\n    alice.login(),\n    bob.login(),\n  ]);\n  await waitUntil(() => alice.loggedIn && bob.loggedIn);\n\n  // Step 3: use *Virtual helpers from here on\n  await configureLocalBootstrapVirtual(scenario);\n  await Future.wait([\n    establishFriendshipVirtual(scenario, alice, bob),\n  ]);\n});\n```\n\n**顺序很重要。** `enableEarly` 必须在 `initAllNodes` 之前运行，让构造函数继承标志；如果忘记它，只在之后调用 `enableForScenario`，信令测试会挂住，因为 `event_thread` 已经启动，`task_queue` 的所有权变得模糊。完全不碰信令的群组测试可以跳过 `enableEarly`，但默认“一律先调用 `enableEarly`”没有成本。\n\n---\n\n## 5. 群邀请重试模式\n\n群邀请可能与 loopback 上的 NGC peer discovery 竞争。等待 `onGroupInvited` 时，用一个很小的重试循环包住等待，并在每次 miss 后重新发出 `inviteUserToGroup`：\n\n```dart\nvar arrived = false;\nfor (var attempt = 0; !arrived && attempt < 3; attempt++) {\n  if (attempt > 0) {\n    member.clearCallbackReceived('onGroupInvited');\n    await founder.runWithInstanceAsync(() async =>\n        TIMGroupManager.instance.inviteUserToGroup(\n          groupID: groupId,\n          userList: [member.getPublicKey()],\n        ));\n  }\n  try {\n    await waitUntilWithVirtualPump(\n      scenario,\n      () => member.callbackReceived['onGroupInvited'] == true,\n      timeout: const Duration(seconds: 15),\n      description: '${member.alias} onGroupInvited (attempt ${attempt + 1})',\n    );\n    arrived = true;\n  } catch (_) {\n    // Retry up to 3 times.\n  }\n}\nexpect(arrived, isTrue,\n    reason: '${member.alias} did not receive onGroupInvited after 3 attempts');\n```\n\n第一次 `inviteUserToGroup` 发生在循环之前（上面为简洁省略）；循环只在重试时重新发起邀请。\n\n---\n\n## 6. 易错点\n\n- **`wallSleep` 不是可选项。** Loopback UDP 往返需要真实 wall time。默认 5 ms 适合好友 P2P 握手；对 conference 这类多步包投递流程应提高到 30–200 ms，例如在 `pumpTestTickAv` 中使用 `wallSleep: const Duration(milliseconds: 50)`。\n- **`pumpTestTick` 每次调用会跑一轮 iterate**，但会随 `advanceMs` 自动放大。`pumpTestTick(advanceMs: 3000)` 会对每个实例执行 60 次 iterate（`floor(3000/50)`），不是 1 次。如果需要更高 iterate 密度而不推进更多时间，传入 `iterationsPerInstance: N`，helper 会使用 `max(N, advanceMs/50)`。\n- **批量 iterate。** 有效迭代次数 >=10 时，helper 会切成 10 个批次，批次之间让出 2 ms wall time，避免包突发堆积在 OS socket buffer 里。\n- **测试模式下 `RunOnEventThread` inline 执行**，不会因为等待 `event_thread` 产生 future-wait 死锁。\n- **`task_queue` 由 `tim2tox_ffi_iterate_instance` 同步 drain**（每次 `pumpTestTick` 都会调用它），所以 `PostToEventThread` 任务（信令派发、conversation manager 工作等）仍会执行，只是运行在线程测试线程上，而不是 event thread 上。\n- **ToxAV 需要 AV pump。** 任何依赖通话状态转换或音视频帧投递的测试，都要使用 `pumpTestTickAv` / `waitUntilWithAvVirtualPump`。默认 `pumpTestTick` 不会触碰 ToxAV。\n- **`enableEarly` 是进程级开关。** 一旦打开，之后构造的每个 `V2TIMManagerImpl` 都会进入测试模式。若某个测试要在同一进程中混用 test-mode 和 non-test-mode 实例，需要用 `tim2tox_ffi_set_test_mode(handle, 0)` 让特定实例退出测试模式。\n- **虚拟模式不会修复协议 flake。** DHT、好友 P2P、群 announce 的 flake 与时钟来源无关。wall 模式下会抖的测试，在 virtual 模式下预计也会等价抖动，而不是更差或更好。\n\n---\n\n## 7. C++ 内部机制（给读源码的工程师）\n\n| 符号 | 位置 | 用途 |\n|---|---|---|\n| `g_default_test_mode` | `source/V2TIMManagerImpl.cpp` | 进程级 atomic 标志；`V2TIMManagerImpl` 构造函数会读入 `test_mode_`。 |\n| `tim2tox_ffi_set_default_test_mode(int)` | `ffi/tim2tox_ffi.cpp` | 翻转 `g_default_test_mode`。由 `VirtualClock.enableEarly()` 调用。 |\n| `tim2tox_ffi_set_test_mode(handle, int)` | `ffi/tim2tox_ffi.cpp` | 在构造后翻转既有实例的 `test_mode_`。`VirtualClock.enableForScenario()` 会对每个节点调用它。 |\n| `tim2tox_ffi_set_virtual_time_ms(uint64_t)` | `ffi/tim2tox_ffi.cpp` | 存储共享虚拟时钟值，供 `tim2tox_virtual_time_cb` 读取。 |\n| `tim2tox_ffi_iterate_instance(handle)` | `ffi/tim2tox_ffi.cpp` | drain `task_queue`、调用 `tox_iterate`，并在 `V2TIMSignalingManagerImpl` 中通过 `mono_time` 检查邀请超时。它是测试 harness 驱动的单一 chokepoint。 |\n| `mono_time_set_current_time_callback` | c-toxcore public API | 每个 Tox 实例的当前时间回调。测试模式下会在 `InitSDK` 阶段为每个实例安装一次（`V2TIMManagerImpl.cpp` 约 line 404），接到读取全局虚拟时钟的 `tim2tox_virtual_time_cb`。 |\n\n这意味着所有 Tox 内部定时器（`mono_time_is_timeout`、`PING_INTERVAL`、`BAD_NODE_TIMEOUT`、onion path 过期）都会读取同一个共享时钟；从 Dart 推进它，就会立刻让每个实例的内部定时器同步快进。\n\n---\n\n## 8. 性能预期\n\n来自近期一次 `RUN_VIRTUAL=1` 跨 phase 运行的经验数据（macOS、M-series、loopback）：\n\n| Phase | Wall | Virtual | 加速比 |\n|---|---|---|---|\n| Phase 4 (group)         | 269 s | 213 s | 1.26× |\n| Phase 10 (group ext)    | 569 s | 287 s | 1.98× |\n| Phase 12 (other)        | 218 s | 158 s | 1.38× |\n\n典型的多实例、`setUpAll` 重的 phase 可接近 2×。单实例或小 phase（Phase 1 basic、Phase 14 unit）收益很小，因为它们没有卡在 Tox 协议定时器上。\n\n上限由 `pumpTestTick` 内的 loopback wall sleep 决定；把 `advanceMs` 提到约 3000 以上不会进一步减少 wall time，因为真实包投递开始占主导。\n\n---\n\n## 9. 编写 mode-aware 场景\n\n场景是**单个 mode-aware 文件**；不存在 `*_virtual_test.dart` 兄弟文件。一个文件默认跑 wall-clock，在 `RUN_VIRTUAL=1` 下跑 virtual-clock。新建 `scenario_foo_test.dart` 时，要让它同时支持两种模式：\n\n1. 用 `shouldRunVirtual`（来自 `test_helper.dart`）保护 clock-enable 调用：在 `setupTestEnvironment()` 之后立即执行 `if (shouldRunVirtual) await VirtualClock.enableEarly();`；在 `initAllNodes()` 之后立即执行 `if (shouldRunVirtual) await VirtualClock.enableForScenario(scenario);`。Wall 模式下这些调用会跳过，`event_thread` 正常运行。\n2. 在测试体里无条件使用第 3 节的 `*Virtual` helper，并把 `scenario` 传下去。它们在时钟未启用时都会回退到 real-time 行为，所以同一份测试体可服务两种模式：\n   - 固定 deadline pump（`pumpFriendConnectionVirtual`、`pumpGroupPeerDiscoveryVirtual`、`establishFriendshipVirtual`、`waitUntilFounderSeesMemberInGroupVirtual`）会在 `!VirtualClock.enabled` 时委托给 wall-clock 等价函数；\n   - 连接等待器（`waitForConnectionVirtual`、`waitForFriendConnectionVirtual`）会委托给 `TestNode` 的 real-time 方法；`pumpTestTick` / `waitUntilWithVirtualPump` 会委托给 `pumpAllInstancesOnce` / `waitUntilWithPump`。\n3. 用 `pumpTestTick(scenario, advanceMs: N)` 替代 `Future.delayed(Duration(milliseconds: N))`。ToxAV 使用 `*Av` pump。\n4. **内联轮询循环不要直接以 `VirtualClock.nowMs` 为门槛**，除非循环体里通过 `pumpTestTick` 前进时钟（它的 wall fallback 也会推进 Dart 侧计数器）。裸写 `while (VirtualClock.nowMs < deadline)` 且内部没有 `pumpTestTick`，会在 wall 模式下永久自旋；这种场景应使用基于 `DateTime` 的 deadline。\n5. 验证**两种模式**：`flutter test test/scenarios/scenario_foo_test.dart` 和 `RUN_VIRTUAL=1 flutter test test/scenarios/scenario_foo_test.dart`。Virtual 模式应该匹配 wall 模式可靠性，而不是超过它。\n\n---\n\n## 参考\n\n- [auto_tests/README.zh-CN.md](README.zh-CN.md) — 高层概览与 Phase 覆盖表\n-
